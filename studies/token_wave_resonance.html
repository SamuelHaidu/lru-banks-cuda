Token waves: binding by resonance

Each token carries a wave: a complex number per channel, a·eiθ. A bank adds the waves of the tokens in context. Tokens whose phases agree add up (they resonate); tokens with unrelated phases cancel on average. Click words to switch them on and off. The waves here are synthetic, designed to show the mechanism: tokens of the same group (entity, place, action, opening) share a phase pattern; function words have random phases.

How this maps to the model

Today: a bank adds RoPE-rotated token vectors, so a token's phase comes only from its position. Adjacent tokens agree in slow channels, so "icy hill" already adds up there, but nothing lets two tokens choose to be in tune, and nothing reads the energy |M| (the readout is linear in M).

Option A, phase per token: angle = position·ω + φb[token]. Tokens with the same role learn similar φ and resonate when they co-occur. The per-token rotation folds into the virtual embedding tables (free at run time), and the MLP gets the per-channel magnitudes |Mb,c| as extra inputs so it can read the resonance directly.

Option B, frequency + phase per token: angle = Ωtoken·(distance) + φtoken. As the query moves on, two tokens with the same frequency keep a constant relative phase (their alignment persists); tokens with different frequencies drift and beat, so their interference averages out over time - unrelated pairs fade on their own. Note the relative phase of two same-frequency tokens still depends on their separation (Ω·Δpos), so groups should use slow frequencies. Exact parallel training needs a small codebook of frequency bands (each band pooled with the usual trick).

Why it is cheap: the bank never forms pairs. It keeps one sum per channel, and the pairwise agreement of every token in the window is already inside |M|2.
