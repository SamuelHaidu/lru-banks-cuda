How a slot-memory recurrent model reads, writes and fails

A 32.8M-parameter lru-banks model trained on 0.5B tokens of text and code, taken apart: what it chooses to store, what each read retrieves, what the second hop adds, where its knowledge sits, and the tokens it still gets wrong.

Model: 4 layers × 2 hops, width 512, tied 32,768 × 512 embedding, 8 bank heads × 64, 128 slots per layer, trained write gates, reads held open. Snapshot at epoch 13 (≈0.26 of a pass, lr 1e-3). Measurements on 32,749 validation targets of pretrain-mix-bpe32768 unless noted; every “silenced” number is the validation loss increase in nats per token when that part's output is removed from the stream. memory   weights (FFN)   failure

1 · Entering the networkThe first FFN finishes the embedding

Silencing layer 0's FFN raises the loss by +5.90 nats, more than removing every memory read of the network (2.74 → 8.64). Nothing downstream works without it. With an unfactorized table each token enters as a raw 512-vector; the first FFN turns it into the representation the rest of the network expects, and the hardest-hit tokens are word fragments (inary, erman) whose meaning depends on the token itself rather than on context.

Transformers show the same division of labor: the earliest layers “detokenize”, building word-level features out of sub-word tokens, and models are far less robust to deleting early (and final) layers than middle ones — Lad, Lee, Gurnee & Tegmark, The Remarkable Robustness of LLMs: Stages of Inference?

2 · WritingThe first layer stores what is new, and skips what is predictable

Each token can write into the banks of every layer, per head, through a binary gate the model learned. Layer 0 writes 61% of (token, head) pairs; layers 1–3 write 79%, 74% and 66%. What layer 0 keeps is not random:

Layer 0 indexes content. Content-word starts are written by 80% of heads, function words by 47%, punctuation by 42%. A token seen before in the document is written by 49% of heads against 72% the first time: the memory already holds it. The tails of a rare word, once its first piece is in, are skipped too.
The upper layers keep structure. Layers 1–3 write newlines more than anything (91%, 85%, 74%); in code a newline marks a statement boundary, a position landmark for what follows.
Surprise as the trigger for memorizing is the design principle of Titans (Behrouz, Zhong & Mirrokni), whose neural memory updates in proportion to how unexpected an input is. Here the same policy emerged from a binary gate trained only on next-token loss.

3 · ReadingHop 1 is the memory; it fades with distance

The hop-1 read of layer 0 is the single most important memory path: silencing it costs +1.37, on repeated and new tokens alike. Its cost on a token that already appeared grows with the distance back to that appearance — and so does the intact model's loss: memory fades.

Reads are broad. Each one spreads its attention over about a dozen slots (entropy ≈2.5 nats) and more than half of the mass lands on slots with half-lives under 16 tokens: the banks mostly serve recent context, with a thinner channel to the slow slots. Layer 3 reads the oldest content.

4 · The second hopA different question, mostly about entities in context

After the FFN, each layer forms a second query and reads the same banks again. The second query differs from the first (cosine ≈0.3 per head), so the FFN does turn the stream into a new question. Together the four hop-2 reads are worth +0.23 nats; any single one is nearly redundant (+0.02 to +0.05), so they back each other up. The cost is larger on repeated tokens (+0.27) than new ones (+0.20), and the tokens that suffer most belong to the document's own subject — its names, terms and identifiers: tur, glass, Con, fandom, monetary, else, ↵⇥⇥, Pascal.

What it is not, yet: silencing shows hop 2 is needed for these tokens, not that it chains two lookups (read A, which points to B). That would need the 2-hop recall task on this model, or tracing the slots hop 2 reads against what hop 1 returned.

5 · Deeper layersKnowledge in the weights, syntax in the memory

FFNs of layers 1–2 hold knowledge. They help new tokens 2.6–4× more than repeated ones (layer 2: +0.39 vs +0.10). Their hardest-hit tokens are content that cannot be copied from context: ↵ , name, few, Mars, atmosphere, whether.
Middle-layer reads track syntax. Layer 1's hop-1 read matters most for closing brackets and quotes — ):, "), ),, ],, Con, ); — tokens whose prediction requires remembering what was opened.
Layer 3 shapes the output. Its FFN costs the same on repeated and new tokens and most on function words: power, long, work, interest, issues, trans. Its hop-1 read is nearly unused (+0.10).
FFN layers act as key–value memories whose keys match input patterns and whose values push the output distribution — Geva, Schuster, Berant & Levy, EMNLP 2021. The progression from detokenization through feature building to output sharpening is the depth picture of Lad et al.

6 · FailuresWhere the model struggles

It does not yet copy arbitrary sequences. A random 100-token sequence shown twice is predicted only 4.1 nats better the second time — 9.2 nats, still close to a uniform guess (10.4) — and the second copy does not improve as it goes. The memory retrieves a broad mixture of recent context, not the exact successor of a remembered token. The architecture can copy (a model of this family trained on copying reaches 99.99% at length 64), so this is a capacity the language model has not learned yet.

In transformers, induction heads — attention that finds the previous occurrence of the current token and copies its successor — form in a sudden phase change early in training, and account for most in-context learning — Olsson et al., In-context Learning and Induction Heads. Recurrent and state-space models are known to lag behind attention on exact recall and copying: Arora et al., Zoology; Jelassi et al., Repeat After Me.

Rare tokens and new names cost the most. Loss falls steeply with a token's frequency, and memory rescues rare tokens only when they already appeared in the document:

7 · SummaryWhat the model does, in one paragraph

The first layer's FFN completes the embedding; its gates write new content words into the banks and skip predictable tokens and repeats. One read — layer 0, hop 1 — carries most of the memory, retrieving a broad mixture of recent context whose value fades with distance. Second hops ask a different question after the FFN and resolve references back into the document, backing each other up. The middle layers' FFNs hold knowledge for tokens the context cannot supply, the middle reads track open brackets and quotes, and the last layer shapes the output distribution. It has not yet learned exact copying of unseen sequences, struggles with rare tokens and unannounced switches, and its use of context peaks around a hundred tokens back.

Next measurements: the same study at the end of training (does induction appear?); the 2-hop recall task on this model; balancing the router and matching slot lifetimes to the distances the reads need.

MethodsHow these numbers were measured

Silencing: lbc eval/dump --silence layer:1|2|ffn|all removes a part's output from the residual stream at inference; the trained model is unchanged. Zeroing pushes later layers off their training distribution, so costs are upper bounds on a part's contribution. Per-token losses from lbc dump (64 rows × 512 tokens from document starts); “repeated” means the target token appeared earlier in the same document. Reads: a float64 replay of the C++ model on two rows that records every read's attention over slots (scripts/analyze_reads.py). Induction: documents made of a random sequence of 100 tokens drawn from the vocabulary, written twice. Scripts: ad_hoc_scripts/lbc_study.py, lbc_report.py.
