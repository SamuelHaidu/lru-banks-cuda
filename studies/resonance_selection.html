Selection by resonance: banks tuned like oscillators

Every token has a frequency and a phase; every bank has a frequency, a phase and a sharpness (Q). A token's prior in a bank is how strongly it resonates with the bank: tuned tokens get a high weight, detuned ones almost none. So the per-token, per-bank prior table becomes two numbers per token, and tokens with nearby frequencies are selected together: the grouping comes from the spectrum. Retune a bank (or let the context retune it) and it selects a different group. Waves are synthetic: entity, place, action and opening words sit in four frequency bands; function words are scattered.

The context knob stands for the state of the text (for example the general state): it retunes bank 1 from the entity band toward the place band. The same bank then selects different words, which is context-dependent feature selection with no new parameters per token.

Spectrum tokens at their frequencies (height = amplitude), banks as resonance curves

A token's prior in a bank = the bank's curve height at the token's frequency x the phase match. Sharp banks (high Q) select a narrow band; broad banks (low Q) mix neighbouring groups.

How this maps to the model

Today: each bank has its own prior per token (64 banks x 10k tokens = 640k free numbers), learned independently. Nothing ties "hill" in bank 4 to "hill" in bank 7, or "hill" to "mountain".

With resonance: each token has a frequency and a phase (or a few of each), each bank a frequency, phase and Q. Priors become priorb(t) = resonance(token, bank): 2-3 numbers per token instead of one per bank, and words with similar roles end up in the same band, so they are selected together by every bank tuned there. Adding banks is cheap (3 numbers each).

Context feature selection: let the bank's frequency depend on the context, ωb = fb(general state). The same bank then pulls places in one passage and characters in another. It stays exactly parallel: the weight of token s for query q is a scalar function of (token s, context at q), so the banded weighted sum works as now; only the weight table is per query instead of per token (cost like the bank sums, far below attention).

Together with the clock: the resonance prior can also drive the bank's clock (time advances by the prior), so the tokens a bank resonates with form its compact sequence.
