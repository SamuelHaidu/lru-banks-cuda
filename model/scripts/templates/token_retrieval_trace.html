Why this report

Unlike `alibi-retriever-sphere`'s free query (compared against the entire vocabulary), this architecture's query is compared only against the tokens already present in the context window. Each context position gets a softmax weight from that in-context comparison, and those weights are then scattered into a vocabulary-sized bucket by token id -- so only ids that actually occur in the prompt can end up with nonzero retrieval weight. This report shows, per prompt: Block 1's causal attention, the per-position in-context softmax weight, and the resulting token-id buckets that get pooled from the big table. Retrieval invariance is the cosine similarity between this prompt's real retrieved vector and the vector a perfectly uniform bucket would produce (1.0 = retrieval carries no prompt-specific information). Cases are sorted from least to most invariant, so the prompts where retrieval is most content-dependent come first. The ablation columns compare the real next-token rank of the target name against its rank when the retrieved vector is replaced by the exact uniform-bucket vector, using every other weight unchanged.
