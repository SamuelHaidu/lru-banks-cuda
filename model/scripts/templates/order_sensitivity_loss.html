Why this report

Retrieval was already shown to contribute almost nothing query-specific (see retrieval-ablation-loss). That leaves two candidates for how the model recalls context: the attention blocks doing genuine positional routing, or the final readout FFN (dense1/2/3, a fixed function of one flattened vector) acting as a key-value memory over aggregate context content, indifferent to word order. Nothing else in this architecture mixes information across positions -- ALiBi's positional bias depends only on the absolute index gap, not token identity -- so this is a clean, weight-free test:

A large Δ under shuffled_order means sequence order matters -- and since nothing but attention can exploit order in this architecture, that implicates the attention blocks doing real positional work. A large Δ under masked_target means the specific identity of the earlier occurrence matters, not just something occupying that slot. If both stay small, the final FFN is likely reading aggregate, order-insensitive content from the flattened residual stream rather than a routed, position-specific copy of the target.
